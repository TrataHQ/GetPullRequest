When an agent session completes successfully, GPR opens a pull request on your behalf against the base branch you configured. The PR includes the agent's code changes, a generated description summarising what was done and why, and a link back to the original Jira or GitHub issue. Your job from here is to review the diff, confirm the changes match your intent, and merge when you're satisfied.

## What GPR adds to the PR

Before you start reviewing, familiarise yourself with what GPR includes automatically:

- **PR description** — A plain-English summary of the changes, generated by the agent, including the files touched and the reasoning behind key decisions.
- **Verification badge** — A status check showing whether lint, tests, and build all passed on the local machine before the PR was opened.
- **Session link** — A link to the full session log so you can trace every file read and command run.
- **Issue reference** — A `Closes TASK-123` line that auto-closes the Jira or GitHub issue when the PR is merged.

<Note>
The verification badge represents checks run on your local machine by GPR, not GitHub Actions. Your repository's CI pipeline will still run its own checks after the PR is opened.
</Note>

## Review from GitHub

<Steps>

### Open the pull request

Navigate to the **Pull requests** tab in your GitHub repository and open the PR. Alternatively, use the direct link from the Slack notification or from the CLI:

```bash
gpr task list --status pr_open
```

This shows all tasks with open PRs, including their PR URLs, so you can navigate directly to the right one.

### Read the PR description

The description follows a consistent structure:

```text
## What changed
- Added `RetryHandler` class in `src/payments/retry.ts`
- Updated `PaymentProcessor.process()` to call `RetryHandler` on 5xx errors
- Added unit tests covering 3 retry scenarios

## Why
Resolves TASK-123: The payment processor had no retry logic, causing
single transient failures to surface as user-facing errors.

## Verification
✔ npm test — 20 tests passed
✔ eslint — no errors
```

Read this section first to confirm the agent understood the task correctly before diving into the diff.

### Review the diff

Click **Files changed** to see the full diff. Focus on:

- **Logic correctness** — Does the implementation match the task description?
- **Scope creep** — Did the agent touch files unrelated to the task? If so, leave a comment asking for those changes to be reverted or split into a separate PR.
- **Test coverage** — Are new code paths covered by tests added in the same PR?

Leave inline comments on any line by clicking the `+` icon that appears when you hover over it.

### Approve or request changes

When you're satisfied, click **Review changes** → **Approve**. If you need the agent to revise the work, click **Request changes** and describe what needs to change in your review comment.

<Tip>
To have GPR automatically re-run the agent with your review comments as additional context, use the CLI after submitting your review: `gpr task assign TASK-123 --agent claude-code --context "See GitHub review comments on PR #214."` GPR starts a new session with your context note fed to the agent.
</Tip>

### Merge

Once the PR is approved and all status checks pass, click **Merge pull request**. GPR recommends **Squash and merge** for agent-generated work to keep your commit history clean—one commit per task.

</Steps>

## Review from the CLI

<Tabs>
  <Tab title="Check PR status">
    List tasks that have open PRs to find what needs your attention:

    ```bash
    gpr task list --status pr_open
    ```

    ```
    KEY        TITLE                               STATUS    PR
    TASK-123   Add retry logic to payment proc.    pr_open   #214
    TASK-119   Update API rate limit headers       pr_open   #211
    ```

    Run the review command to open the PR in your browser and display a summary:

    ```bash
    gpr pr review TASK-123
    ```

    ```
    PR #214 — Add retry logic to payment processor
    Branch:  feature/task-123-retry-logic → main
    Files:   3 changed  (+163 −3)
    Checks:  ✔ npm test · ✔ eslint

    Opening https://github.com/your-org/your-repo/pull/214 ...
    ```
  </Tab>
  <Tab title="Approve & merge">
    After reviewing on GitHub, you can complete the merge from the CLI once the PR is approved:

    <CodeGroup>
    ```bash Squash merge (recommended)
    gpr pr review TASK-123 --action merge --strategy squash
    ```

    ```bash Merge commit
    gpr pr review TASK-123 --action merge --strategy merge
    ```

    ```bash Rebase
    gpr pr review TASK-123 --action merge --strategy rebase
    ```
    </CodeGroup>

    <Warning>
    Merging via GPR still respects branch protection rules. If your repository requires a minimum number of approvals, you must gather those approvals before the merge succeeds.
    </Warning>
  </Tab>
</Tabs>

## Review and merge from the mobile app

<Steps>

### Open the PR

Tap **Tasks** → **TASK-123** → **View Pull Request**. The PR detail screen loads the description, changed file list, and status checks.

### Browse the diff

Tap **Files Changed** to see the list of modified files. Tap any file to open a side-by-side diff view. Swipe left to see the new version, swipe right for the original.

### Leave a comment

Long-press any diff line to open the comment drawer. Type your comment and tap **Post**. The comment appears on the GitHub PR immediately.

### Approve and merge

Tap the **Review** button at the bottom of the PR detail screen. Select **Approve**, optionally add a review note, and tap **Submit Review**.

Once approved, tap **Merge** → confirm the merge strategy → **Confirm Merge**. The task card moves to **Merged** and the linked Jira issue closes automatically.

<Tip>
Enable **Merge notifications** in the GPR app settings to get a push notification confirming the merge completed and the issue was closed.
</Tip>

</Steps>

## After merging

GPR automatically:

- Deletes the feature branch (if you have `auto_delete_branch: true` in your GPR config)
- Closes the linked Jira or GitHub issue
- Posts a merge confirmation to the Slack channel configured for notifications

To adjust any of these behaviours, run `gpr config --help` to see available settings.
