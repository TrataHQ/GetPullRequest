---
title: "Connect Your Local Machine to the GPR Orchestrator"
sidebarTitle: "Connect Machine"

GPR runs coding agents directly on your machine—not in a remote cloud container. This is what makes the workflow trustworthy: the agent uses your actual repository checkout, your installed dependencies, and your real test runner. Before any task can execute, GPR needs to know about your machine and establish a secure persistent connection to it.

## What `gpr connect machine` does

When you run `gpr connect machine`, the CLI:

1. **Generates a machine identity** — a unique name and ID that appear in your GPR dashboard.
2. **Opens an encrypted tunnel** — a lightweight, outbound-only WebSocket connection from your machine to the GPR relay. No inbound ports or firewall changes are needed.
3. **Registers your environment metadata** — OS, shell, and detected runtimes (Node, Python, Go, etc.) so GPR can route compatible tasks to this machine.

<Note>
  The tunnel is outbound-only. GPR never opens a port on your machine. Traffic flows: `GPR cloud → relay → your machine`, initiated by your machine's process.
</Note>

## Connect your machine

<Steps>
  <Step title="Run the connect command">
    In your terminal, run:
    ```bash
    gpr connect machine
    ```
  </Step>
  <Step title="Name your machine (optional)">
    GPR auto-generates a name like `dana-macbook-pro`, but you can set a custom one:
    ```bash
    gpr connect machine --name "work-laptop"
    ```
    Machine names appear in the dashboard and in task logs, so choose something you'll recognise.
  </Step>
  <Step title="Approve the registration">
    GPR prints a confirmation prompt:
    ```
    Registering machine "work-laptop"...
    Machine ID: mch_01hx9k2p3qr7v8n5
    ✓ Connected. This machine is now online in team acme-eng.
    ```
    The process continues running in your terminal, keeping the tunnel alive.
  </Step>
  <Step title="Run as a background service (recommended)">
    To keep the connection alive after you close the terminal, install GPR as a system service:

    <Tabs>
      <Tab title="macOS (launchd)">
        ```bash
        gpr service install
        gpr service start
        ```
        GPR registers a `launchd` agent that starts automatically at login.
      </Tab>
      <Tab title="Linux (systemd)">
        ```bash
        gpr service install
        sudo systemctl enable --now gpr
        ```
      </Tab>
      <Tab title="Windows (Task Scheduler)">
        Run in an **elevated** PowerShell prompt:
        ```powershell
        gpr service install
        gpr service start
        ```
      </Tab>
    </Tabs>
  </Step>
</Steps>

## Verify the connection

Check that GPR sees your machine as online from another terminal window (or after reinstalling the service):

```bash
gpr machine list
```

Expected output:

```
ID                    NAME            STATUS    RUNTIMES               LAST SEEN
mch_01hx9k2p3qr7v8n5  work-laptop     online    node 20, python 3.12   just now
```

You can also verify from the **GPR dashboard** at [app.getpr.dev/machines](https://app.getpr.dev/machines)—your machine should appear with a green **Online** badge.

<Tip>
  If you use multiple machines (e.g. a desktop and a laptop), repeat `gpr connect machine` on each one. GPR can route tasks to any online machine and will queue them if all machines are offline.
</Tip>

## Manage connected machines

```bash
# View all machines in your team
gpr machine list

# Rename a machine
gpr machine rename mch_01hx9k2p3qr7v8n5 "home-desktop"

# Take a machine offline gracefully
gpr machine disconnect mch_01hx9k2p3qr7v8n5

# Remove a machine permanently
gpr machine remove mch_01hx9k2p3qr7v8n5
```

<Warning>
  Removing a machine is permanent. Any tasks queued for that specific machine will be reassigned to another online machine in your team, or will remain queued if no other machines are available.
</Warning>

## What's running on your machine

The `gpr connect machine` process (or the background service) is a single lightweight daemon. It:

- Maintains an outbound WebSocket connection (~1 MB idle memory)
- Listens for task dispatch events from the GPR orchestrator
- Launches and supervises the coding agent process when a task arrives
- Streams logs back to GPR in real time
- Reports task success or failure and uploads diffs for PR creation

It does **not** index your codebase, read files outside the working directory of a task, or retain any code after a task completes.
