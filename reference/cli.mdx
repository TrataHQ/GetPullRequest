The `gpr` command-line interface is your primary control plane for GPR. You use it to register machines, connect integrations, manage AI coding agents, and orchestrate tasks—all from your terminal or, via the mobile app, from your phone. Every operation that GPR performs can be driven through this CLI.

---

## Global Flags

These flags apply to every `gpr` subcommand.

<ParamField query="--debug" type="boolean" default="false">
  Emit verbose debug output, including HTTP requests, agent stdout, and internal state transitions. Useful when diagnosing connectivity or task failures.
</ParamField>

<ParamField query="--config" type="string">
  Path to a custom config file. Defaults to `~/.gpr/config.yaml`. Project-level `gpr.yaml` files are merged on top of the global config automatically.
</ParamField>

<ParamField query="--output, -o" type="string" default="text">
  Output format. Accepts `text`, `json`, or `yaml`. Use `json` or `yaml` for scripting and CI pipelines.
</ParamField>

<ParamField query="--profile" type="string">
  Named configuration profile to use. Profiles let you switch between multiple GPR workspaces or accounts.
</ParamField>

<ParamField query="--no-color" type="boolean" default="false">
  Disable ANSI color codes in output. Set automatically when stdout is not a TTY.
</ParamField>

<ParamField query="--version, -v" type="boolean">
  Print the installed GPR version and exit.
</ParamField>

<ParamField query="--help, -h" type="boolean">
  Print help text for the current command and exit.
</ParamField>

## gpr connect

The `gpr connect` family of commands authenticates GPR with external services and registers your local machine as a worker. Run these commands once during initial setup; credentials are stored securely in `~/.gpr/credentials.yaml`.

---

### gpr connect machine

```text
gpr connect machine [flags]
```

Registers your local machine with GPR so it can receive tasks and run AI coding agents. The command opens a short-lived secure tunnel, exchanges a signed token with the GPR cloud, and writes the machine credentials locally. Your machine's status immediately becomes visible in the GPR dashboard and to other CLI commands.

<ParamField query="--name" type="string">
  Human-readable name for this machine (e.g. `dev-laptop`, `home-workstation`). Defaults to the system hostname. Appears in `gpr machine list` and task assignment commands.
</ParamField>

<ParamField query="--tags" type="string">
  Comma-separated labels to attach to this machine (e.g. `--tags gpu,fast-ssd`). Tags let you target specific machines when assigning tasks.
</ParamField>

<ParamField query="--workspace-root" type="string">
  Absolute path on this machine where GPR will clone repositories and run agents. Defaults to `~/gpr-workspace`.
</ParamField>

<ParamField query="--token" type="string">
  Use an existing machine token instead of performing interactive OAuth. Useful for headless servers and CI environments.
</ParamField>

<CodeGroup>
```bash Interactive registration
gpr connect machine --name dev-laptop
```

```bash Headless server with token
gpr connect machine --name ci-runner --token $GPR_MACHINE_TOKEN
```

```bash With tags and custom workspace root
gpr connect machine --name gpu-box --tags gpu,linux --workspace-root /data/gpr
```
</CodeGroup>

<Note>
  A machine must be online and registered before it can receive tasks. If your machine goes offline, tasks assigned to it queue until it reconnects, unless you set a timeout in your config.
</Note>

### gpr connect github

```text
gpr connect github [flags]
```

Authorizes GPR to read and write repositories, open pull requests, and manage webhooks on your behalf via GitHub OAuth. A browser window opens to complete the GitHub authorization flow; the resulting token is stored in `~/.gpr/credentials.yaml`.

<ParamField query="--org" type="string">
  GitHub organization to authorize access for. You can authorize multiple organizations by running the command multiple times with different `--org` values.
</ParamField>

<ParamField query="--github-app" type="boolean" default="false">
  Authenticate as a GitHub App installation rather than a personal OAuth token. Requires your GitHub App ID and private key to be set in config first.
</ParamField>

<ParamField query="--scopes" type="string">
  Comma-separated list of OAuth scopes to request. Defaults to `repo,read:org,workflow`. Only change this if you know what you're doing.
</ParamField>

<CodeGroup>
```bash Personal account
gpr connect github
```

```bash Organization account
gpr connect github --org mycompany
```

```bash GitHub App authentication
gpr connect github --github-app
```
</CodeGroup>

<Warning>
  GPR requires the `repo` scope to open pull requests. If you authorize with restricted scopes and PR creation fails, re-run `gpr connect github` to refresh with the default scopes.
</Warning>

### gpr connect jira

```text
gpr connect jira [flags]
```

Links GPR to your Jira Cloud or Jira Data Center instance. GPR uses this connection to read issue details when you reference a Jira ticket in a task, post status comments, and transition issue states automatically when a PR is merged.

<ParamField query="--url" type="string" required>
  Base URL of your Jira instance, e.g. `https://mycompany.atlassian.net` or `https://jira.internal.example.com`.
</ParamField>

<ParamField query="--email" type="string">
  Email address associated with your Jira account. Required for Jira Cloud API token authentication.
</ParamField>

<ParamField query="--token" type="string">
  Jira API token (Cloud) or Personal Access Token (Data Center). If omitted, GPR prompts you interactively.
</ParamField>

<ParamField query="--project" type="string">
  Default Jira project key (e.g. `PROJ`) to use when no project is specified in a task command.
</ParamField>

<CodeGroup>
```bash Jira Cloud
gpr connect jira --url https://mycompany.atlassian.net --email me@example.com
```

```bash Jira Data Center
gpr connect jira --url https://jira.internal.example.com --token $JIRA_PAT
```

```bash With default project
gpr connect jira --url https://mycompany.atlassian.net --project PROJ
```
</CodeGroup>

### gpr connect linear

```text
gpr connect linear [flags]
```

Connects GPR to your Linear workspace via OAuth. Once connected, you can reference Linear issue IDs in tasks, and GPR will update issue states and post comments as work progresses.

<ParamField query="--team" type="string">
  Linear team identifier or slug to use as the default team for task creation. You can override this per task.
</ParamField>

<ParamField query="--token" type="string">
  Linear Personal API Key. If omitted, GPR opens the browser OAuth flow.
</ParamField>

<CodeGroup>
```bash Browser OAuth
gpr connect linear
```

```bash Personal API key
gpr connect linear --token lin_api_xxxxxxxxxxxx
```

```bash With default team
gpr connect linear --team eng-platform
```
</CodeGroup>

## gpr agent

Manage the AI coding agents that GPR dispatches work to. GPR supports Claude Code, OpenAI Codex, Cursor, and any agent that implements the ACP (Agent Communication Protocol). Agents are configured per-machine and stored in your GPR config.

---

### gpr agent add

```text
gpr agent add <name> [flags]
```

Registers a named coding agent with GPR on the current machine. `<name>` is one of the built-in agent identifiers (`claude-code`, `codex`, `cursor`) or a custom ACP-compatible agent name. After adding an agent, you can assign tasks to it by name.

<ParamField path="name" type="string" required>
  The agent identifier. Built-in values: `claude-code`, `codex`, `cursor`. For custom ACP agents, use any unique slug.
</ParamField>

<ParamField query="--path" type="string">
  Absolute path to the agent binary or launch script. Required for custom ACP agents. For built-in agents, GPR auto-detects the binary from `$PATH`.
</ParamField>

<ParamField query="--acp-url" type="string">
  HTTP base URL of a running ACP-compatible agent server (e.g. `http://localhost:8080`). Use this when the agent runs as a separate process or service.
</ParamField>

<ParamField query="--env" type="string">
  Comma-separated `KEY=VALUE` pairs to inject into the agent's environment (e.g. `--env ANTHROPIC_API_KEY=sk-...`). Values are stored encrypted in your credentials file.
</ParamField>

<ParamField query="--default" type="boolean" default="false">
  Set this agent as the default for this machine. Tasks assigned to this machine without an explicit agent use this one.
</ParamField>

<CodeGroup>
```bash Add Claude Code as default
gpr agent add claude-code --default
```

```bash Add Codex with API key
gpr agent add codex --env OPENAI_API_KEY=sk-...
```

```bash Add a custom ACP agent
gpr agent add my-agent --acp-url http://localhost:9000
```

```bash Add Cursor with explicit binary path
gpr agent add cursor --path /Applications/Cursor.app/Contents/MacOS/Cursor
```
</CodeGroup>

<Tip>
  Store API keys in environment variables or your system keychain rather than passing them directly on the command line to avoid leaking secrets into your shell history.
</Tip>

<ParamField query="--machine" type="string">

</ParamField>

<ParamField query="--output, -o" type="string" default="text">


## gpr task

Create, assign, monitor, and manage the tasks that GPR orchestrates. A task represents a unit of work—typically tied to a Jira or Linear issue—that GPR assigns to an agent on a registered machine, verifies, and turns into a pull request.

---

### gpr task create

```text
gpr task create <title> [flags]
```

Creates a new GPR task. The task starts in `pending` state. Provide a `--repo` so GPR knows which codebase to work in, and optionally link a Jira or Linear issue to pull in context automatically.

<ParamField path="title" type="string" required>
  Short title describing the work. Wrap in quotes if it contains spaces. This becomes the PR title by default.
</ParamField>

<ParamField query="--repo" type="string" required>
  GitHub repository in `owner/repo` format. GPR clones or updates this repo on the assigned machine.
</ParamField>

<ParamField query="--jira" type="string">
  Jira issue key to link (e.g. `PROJ-123`). GPR pulls the issue description and acceptance criteria into the agent's context.
</ParamField>

<ParamField query="--linear" type="string">
  Linear issue ID or identifier (e.g. `ENG-456`) to link.
</ParamField>

<ParamField query="--branch" type="string">
  Name of the feature branch to create. Defaults to a slug derived from the task title.
</ParamField>

<ParamField query="--base" type="string" default="main">
  Base branch to branch from and target for the pull request.
</ParamField>

<ParamField query="--agent" type="string">
  Agent to assign immediately. If omitted, the task remains `pending` until you run `gpr task assign`.
</ParamField>

<ParamField query="--machine" type="string">
  Machine to run on. If omitted alongside `--agent`, GPR assigns based on availability and your config.
</ParamField>

<ParamField query="--priority" type="string" default="normal">
  Task priority: `low`, `normal`, `high`, `urgent`. Higher-priority tasks preempt lower-priority ones on busy machines.
</ParamField>

<ParamField query="--description" type="string">
  Additional context or instructions for the agent. Appended to the linked issue description, if any.
</ParamField>

<CodeGroup>
```bash Minimal task linked to Jira
gpr task create "Fix login bug" --repo myorg/myapp --jira PROJ-123
```

```bash Fully specified task
gpr task create "Refactor auth module" \
  --repo myorg/myapp \
  --jira PROJ-456 \
  --agent claude-code \
  --machine dev-laptop \
  --branch refactor/auth-module \
  --base main \
  --priority high
```

```bash Task from Linear issue
gpr task create "Add dark mode support" \
  --repo myorg/frontend \
  --linear ENG-789 \
  --agent codex
```

```bash Task with inline description (no issue tracker)
gpr task create "Update README" \
  --repo myorg/myapp \
  --description "Add installation steps for Windows and update badge URLs."
```
</CodeGroup>

### gpr task assign

```text
gpr task assign <id> [flags]
```

Assigns a `pending` (or `failed`) task to a specific agent and/or machine. If the task was created without an agent, this command moves it from `pending` to `assigned` and queues it for execution.

<ParamField path="id" type="string" required>
  GPR task ID (e.g. `TASK-456`). Retrieve IDs with `gpr task list`.
</ParamField>

<ParamField query="--agent" type="string">
  Name of the agent to assign the task to.
</ParamField>

<ParamField query="--machine" type="string">
  Name or ID of the machine to run the task on. If omitted, GPR selects the machine where the named agent is configured as ready.
</ParamField>

<ParamField query="--force" type="boolean" default="false">
  Reassign a task that is already `assigned` or `running`. Use with caution—this interrupts the current execution.
</ParamField>

<CodeGroup>
```bash Assign to agent and machine
gpr task assign TASK-456 --agent claude-code --machine dev-laptop
```

```bash Assign to agent only (GPR picks machine)
gpr task assign TASK-456 --agent codex
```

```bash Force reassign a running task
gpr task assign TASK-456 --agent claude-code --force
```
</CodeGroup>

<Warning>
  Using `--force` on a task in `running` state terminates the current agent execution immediately. Any uncommitted work the agent has done is discarded.
</Warning>

### gpr task status

```text
gpr task status <id> [flags]
```

Displays the current state and detailed metadata for a single task, including agent logs, linked issue, target repository, and any errors.

<ParamField path="id" type="string" required>
  GPR task ID.
</ParamField>

<ParamField query="--watch, -w" type="boolean" default="false">
  Poll and re-render the status every 5 seconds until the task reaches a terminal state (`pr_open`, `merged`, `failed`, or `cancelled`).
</ParamField>

<ParamField query="--logs" type="boolean" default="false">
  Include the last 100 lines of agent output in the status display.
</ParamField>

<CodeGroup>
```bash One-shot status check
gpr task status TASK-456
```

```bash Watch until completion
gpr task status TASK-456 --watch
```

```bash Status with agent logs
gpr task status TASK-456 --logs
```
</CodeGroup>

### gpr task list

```text
gpr task list [flags]
```

Lists all tasks visible to your account, with their IDs, titles, states, assigned agents, and linked issues. Supports filtering and sorting.

<ParamField query="--state" type="string">
  Filter by state. Accepts one or more comma-separated values: `pending`, `assigned`, `running`, `verifying`, `pr_open`, `merged`, `failed`, `cancelled`.
</ParamField>

<ParamField query="--repo" type="string">
  Filter to tasks targeting a specific repository (`owner/repo`).
</ParamField>

<ParamField query="--agent" type="string">
  Filter to tasks assigned to a specific agent.
</ParamField>

<ParamField query="--machine" type="string">
  Filter to tasks assigned to a specific machine.
</ParamField>

<ParamField query="--limit" type="integer" default="25">
  Maximum number of tasks to return.
</ParamField>

<ParamField query="--sort" type="string" default="created_at:desc">
  Sort field and direction. Format: `field:asc|desc`. Valid fields: `created_at`, `updated_at`, `priority`, `state`.
</ParamField>

<CodeGroup>
```bash All tasks
gpr task list
```

```bash Running and failed tasks only
gpr task list --state running,failed
```

```bash Tasks for a specific repo
gpr task list --repo myorg/myapp
```

```bash Paginated with custom sort
gpr task list --limit 50 --sort priority:desc
```

```bash JSON output for scripting
gpr task list --output json
```
</CodeGroup>

### gpr task retry

```text
gpr task retry <id> [flags]
```

Re-queues a `failed` or `cancelled` task for execution. By default, retries use the same agent and machine as the previous attempt.

<ParamField path="id" type="string" required>
  GPR task ID of the failed or cancelled task.
</ParamField>

<ParamField query="--agent" type="string">
  Override the agent for this retry attempt.
</ParamField>

<ParamField query="--machine" type="string">
  Override the machine for this retry attempt.
</ParamField>

<ParamField query="--clean" type="boolean" default="false">
  Delete the working branch and re-clone the repository before retrying. Use this if the workspace was left in a bad state.
</ParamField>

<CodeGroup>
```bash Retry with same settings
gpr task retry TASK-456
```

```bash Retry on a different machine
gpr task retry TASK-456 --machine home-workstation
```

```bash Retry with a clean workspace
gpr task retry TASK-456 --clean
```
</CodeGroup>

### gpr task cancel

```text
gpr task cancel <id> [flags]
```

Cancels a task at any point before it reaches `merged` state. GPR stops the agent process if it is running, closes the GitHub pull request if one has been opened, and records the cancellation. Cancelled tasks cannot be retried in place—create a new task with `gpr task create` to restart the work.

<ParamField path="id" type="string" required>
  GPR task ID (e.g. `TASK-456`). Retrieve IDs with `gpr task list`.
</ParamField>

<ParamField query="--reason" type="string">
  Optional human-readable explanation for the cancellation. Recorded in the task history and included in any configured notifications.
</ParamField>

<CodeGroup>
```bash Cancel a pending or assigned task
gpr task cancel TASK-456
```

```bash Cancel a running task with a reason
gpr task cancel TASK-456 --reason "Scope changed, will re-create with updated requirements"
```

```bash Confirm cancellation
gpr task status TASK-456
```
</CodeGroup>

<Warning>
  Cancelling a task in `running` state terminates the agent process immediately. Any uncommitted changes the agent has made are discarded. If a PR was already open, GPR closes it automatically.
</Warning>

### gpr machine remove

```text
gpr machine remove <id> [flags]
```

Deregisters a machine from your GPR account. Any tasks currently assigned to this machine are moved back to `pending` state so they can be reassigned. The machine's local credentials are not deleted automatically—run `gpr connect machine --revoke` on the machine itself to clean those up.

<ParamField path="id" type="string" required>
  Machine ID (e.g. `mach_a1b2c3`) or machine name. Retrieve with `gpr machine list`.
</ParamField>

<ParamField query="--force" type="boolean" default="false">
  Remove the machine even if it has tasks in `running` or `assigned` state. Those tasks are cancelled, not re-queued.
</ParamField>

<CodeGroup>
```bash Remove by name
gpr machine remove dev-laptop
```

```bash Remove by ID, force
gpr machine remove mach_a1b2c3 --force
```
</CodeGroup>

<Warning>
  Removing a machine with `--force` while tasks are `running` cancels those tasks immediately. Use `gpr task list --machine <id>` first to review active work.
</Warning>

## gpr workspace

---

### gpr workspace init

```text
gpr workspace init [flags]
```

Initializes a GPR workspace in the current directory (or a specified path) by writing a `gpr.yaml` project config file, creating a `.gpr/` directory for local state, and optionally connecting the directory to an existing GitHub repository. Run this command once at the root of each project you want GPR to manage.

<ParamField query="--repo" type="string">
  GitHub repository (`owner/repo`) to associate with this workspace. If omitted, GPR attempts to infer it from the local `git remote origin`.
</ParamField>

<ParamField query="--agent" type="string">
  Default agent to use for tasks in this workspace. Overrides the global default.
</ParamField>

<ParamField query="--jira-project" type="string">
  Jira project key to use by default for tasks created in this workspace.
</ParamField>

<ParamField query="--linear-team" type="string">
  Linear team to associate with this workspace.
</ParamField>

<ParamField query="--path" type="string" default=".">
  Directory to initialize. Defaults to the current working directory.
</ParamField>

<CodeGroup>
```bash Initialize in current directory
gpr workspace init
```

```bash Initialize with explicit repo
gpr workspace init --repo myorg/myapp --agent claude-code
```

```bash Initialize in a different directory
gpr workspace init --path /projects/my-service --repo myorg/my-service
```
</CodeGroup>

## gpr pr

Review and inspect pull requests that GPR has opened on your behalf.

---

### gpr pr review

```text
gpr pr review <task-id> [flags]
```

Opens an interactive review summary for the pull request associated with a given task. The command displays the PR diff, linked issue context, verification results, and any review comments already posted. Use this to quickly assess what the agent changed before approving the PR in GitHub.

<ParamField path="task-id" type="string" required>
  GPR task ID whose PR you want to review (e.g. `TASK-456`). The task must be in `pr_open` state. Retrieve IDs with `gpr task list --state pr_open`.
</ParamField>

<ParamField query="--diff" type="boolean" default="true">
  Show the full unified diff of all changed files. Pass `--diff=false` to skip the diff and show only the PR summary and comments.
</ParamField>

<ParamField query="--open" type="boolean" default="false">
  Open the pull request URL directly in your default browser instead of rendering the review in the terminal.
</ParamField>

<ParamField query="--output, -o" type="string" default="text">
  Output format: `text`, `json`, or `yaml`. Use `json` or `yaml` to pipe PR metadata into other tools.
</ParamField>

<CodeGroup>
```bash Review a PR in the terminal
gpr pr review TASK-456
```

```bash Open the PR in your browser
gpr pr review TASK-456 --open
```

```bash Show summary only (no diff)
gpr pr review TASK-456 --diff=false
```

```bash Export PR metadata as JSON
gpr pr review TASK-456 --output json
```
</CodeGroup>

<Tip>
  Run `gpr task list --state pr_open` first to see all tasks with open PRs, then pass a task ID to `gpr pr review` to inspect each one.
</Tip>

## gpr config

```text
gpr config [key] [value] [flags]
```

View and edit your GPR configuration. With no arguments, prints the full resolved config (global + project). Pass a dotted key path to read a single value, or pass both a key and a value to set it.

<ParamField path="key" type="string">
  Dotted path to the config field (e.g. `machine.name`, `default_agent`, `notifications.slack`).
</ParamField>

<ParamField path="value" type="string">
  New value to set. Omit to read the current value.
</ParamField>

<ParamField query="--global" type="boolean" default="false">
  Write changes to `~/.gpr/config.yaml` even when a project-level `gpr.yaml` is present.
</ParamField>

<ParamField query="--unset" type="boolean" default="false">
  Remove the specified key from the config file.
</ParamField>

<ParamField query="--edit" type="boolean" default="false">
  Open the config file in your `$EDITOR`.
</ParamField>

<CodeGroup>
```bash View full config
gpr config
```

```bash Read a single value
gpr config default_agent
```

```bash Set the default agent
gpr config default_agent claude-code
```

```bash Open config in editor
gpr config --edit
```

```bash Set a nested value globally
gpr config --global notifications.slack true
```

```bash Unset a value
gpr config --unset notifications.email
```
</CodeGroup>
