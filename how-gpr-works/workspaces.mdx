title: "Workspaces"
description: "Workspaces bind a directory on a machine to GPR execution settings."
---

A **workspace** is the user-facing execution identity: a directory on a paired machine where agents run.

## What it stores

| Field | Meaning |
|---|---|
| Working directory | Bound repo / project path |
| Machine | Which paired host runs it |
| Agent | Selected catalog agent id |
| Default model | Defaults to `auto` |
| Provider | Defaults to `byoa` |
| Max concurrent tasks | Defaults to `1` |
| Status | `active` or `archived` |

## Create one

```bash
cd /path/to/repo
gpr setup
```

Pair via QR from the app. Re-running setup in the same directory reconnects; it does not duplicate.

## Affinity

Each task pins to one workspace / daemon. Keep that host online for the life of the run. If the host drops, the task moves to `waiting_for_agent` until it returns.

## Multiple workspaces

One machine can host several workspaces (different directories). Use separate workspaces when repos or agent defaults differ. See [Manage multiple machines](/guides/manage-multiple-machines).

## Code host connection is optional

A connected code host (GitHub, etc.) is an enrichment, not a requirement. Tasks run on your machine with local git and worktrees whether or not a host is connected. Only PR / MR delivery and host issue sync require one.

The base-branch pill on the task card is always actionable. When no host is connected, the branch picker falls back to your local git branches so you can still pick or change the base for a task.

## Local state

Per-workspace daemon data lives under `~/.gpr/workspaces/<workspace_id>/`.
