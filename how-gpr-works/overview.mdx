GPR is a control plane for coding agents that run on machines you own.

## Runtime shape

```text
Flutter app  --HTTPS-->  FastAPI (REST)
Flutter app  --WSS---->  hub / relay  <--WSS--  gpr daemon
                              │
                         optional HTTPS to GitHub / GitLab / Jira / Slack
                              │
gpr daemon  --ACP stdio-->  Cursor / Claude / Codex / …
gpr daemon  --git-------->  local worktrees
```

| Piece | Role |
|---|---|
| Mobile app | Board, chat, review, settings |
| Backend | Auth, task queue, relay, integrations |
| `gpr` daemon | Pairing, ACP host, git worktrees |
| Coding agent | Writes and edits code on the machine |

## Core objects

| Object | What it is |
|---|---|
| [Machine](/how-gpr-works/machines) | Paired computer running the daemon |
| [Workspace](/how-gpr-works/workspaces) | Directory bound to a machine; where tasks run |
| [Task](/how-gpr-works/tasks) | Board item with status, phase, and checkpoint |
| [Agent session](/how-gpr-works/agent-sessions) | Live ACP session tied to a task or chat |
| [Pull request](/how-gpr-works/pull-requests) | Review artifact; GitHub or GitLab is source of truth when connected |

A task pins to one workspace. Do not let a second host take over the same task.

## BYOA by default

Workspaces default to bring-your-own-agent (`provider: byoa`). Agents and credentials live on your machine. The cloud orchestrates; it does not replace your local toolchain.

## Enrichments vs core

Core features work without OAuth: board, sessions, local git, merge-check from the daemon.

[GitHub](/integrations/github), [GitLab](/integrations/gitlab), [Jira](/integrations/jira), and [Slack](/integrations/slack) are optional enrichments. They sync issues, open host PRs / MRs, and add metadata. They never replace local git results.
